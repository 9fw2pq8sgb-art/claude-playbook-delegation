Claude Code · Skill „delegieren“

Opus plant. Sonnet und Haiku arbeiten.

Der Skill lässt das große Modell die Aufgabe zerlegen und für jeden Teil ein präzises Playbook schreiben. Die Ausführung übernehmen günstigere Modelle. Danach prüft das große Modell das Ergebnis gegen ein messbares Gate.

01 · Das Problem und die Idee

Das große Modell macht sonst alles selbst

Suchen, Lesen, Umformen, Tests laufen lassen: Ohne Delegation übernimmt das große Modell auch diese Routinearbeit. Das verbraucht viele Tokens.

Ohne Delegation

Ein Modell plant und führt alles selbst aus.

Token-Last bei Opus: Planung und Ausführung

Mit Delegation

Die Intelligenz steckt im Playbook. Günstige Modelle führen aus.

Opus: Planung und Prüfung (gefüllt) · Haiku/Sonnet: Ausführung (Umriss)

Schematische Darstellung des Prinzips: Der Anteil bei Opus sinkt deutlich. Keine Messwerte.

Jeder Subagent startet mit leerem Kontext. Das kostet Startaufwand. Darum werden Ein-Zeilen-Edits nicht delegiert, sondern nur Aufgaben, bei denen das Playbook kürzer ist als die Arbeit.

02 · Der Ablauf

Vom Auftrag zum geprüften Ergebnis

Sieben Schritte. Besteht das Gate nicht, geht es über den gestrichelten Pfad zurück.

  1. Auftrag
  2. Opus zerlegt
  3. Playbooks
  4. Haiku / Sonnet arbeiten parallel
  5. Agent führt Gate aus
  6. Gate nicht bestanden: Playbook schärfen, zurück zu Schritt 3
  7. Opus prüft selbst nach
  8. Fertig
ABLAUF STARTEN wählen oder mit WEITER schrittweise durchgehen.
03 · Modellwahl

Eine Frage entscheidet

Muss der Agent etwas entscheiden, das nicht im Playbook steht?

Antwort wählen, um das Modell zu sehen.

Im Zweifel Haiku zuerst. Ein Fehlschlag am Gate ist billiger als Sonnet auf Vorrat. Das Modell wird bei jedem Agent-Aufruf explizit gesetzt.

04 · Anatomie eines Playbooks

Sieben Pflichtfelder

Jeder Agent-Auftrag hat genau diese Teile. Beispiel: alle Stellen mit der alten API getUser() auf fetchUser() umstellen.

01

Ziel

Ein Satz. Was am Ende vorliegt.

Alle Aufrufe von getUser() sind
durch fetchUser() ersetzt.
02

Kontext

Absolute Pfade zum Lesen und Fakten, die der Agent nicht selbst herausfinden soll. Keine Inhalte hineinkopieren.

Repo-Pfad (absolut) · alte und
neue Signatur
03

Schritte

Nummeriert, eine Handlung pro Schritt. Entscheidungen vorweg: „nimm X, nicht Y, weil …“.

1. Stellen mit getUser() suchen
2. Je Stelle auf fetchUser() umstellen
04

Verbote

Was der Agent nicht anfasst.

Kein git push, kein Löschen,
keine Nachrichten senden
05

Gate

Der Check, den der Agent selbst ausführt, bevor er „fertig“ meldet. Möglichst mit Gegenprobe: bekannten Fehler einspeisen und prüfen, ob der Check ihn findet.

Test-Kommando des Projekts
06

Stopp

Was bei Abweichung gilt.

Passt etwas nicht zum Playbook:
abbrechen und melden, nicht raten.
07

Rückgabe

Festes, kurzes Format. Keine Prosa.

STATUS: pass | fail | blockiert
DATEIEN · GATE · OFFEN

Ein Playbook ist gut, wenn der Agent ohne Rückfrage fertig wird und das Gate grün ist. Fragt der Agent nach oder rät er, war das Playbook zu dünn, nicht das Modell zu klein.

05 · Prüfen und eskalieren

Fehlschlag: erst schärfen, dann hochstufen

Der Prüfer ist nie der Arbeiter. Meldet ein Agent „pass“, lässt Opus das Gate selbst erneut laufen oder nimmt eine Stichprobe.

Haiku 5.5
Sonnet 5.5
Opus selbst
    Erst Playbook schärfen, dann Stufe hoch.

    Der Skill merkt sich, welcher Aufgabentyp welches Modell brauchte. Das ist die Grundlage für die nächste Modellwahl.

    06 · Umfang

    Was der Skill kann und was er nicht tut

    Kann

    • Entscheiden, ob delegiert oder selbst gemacht wird
    • Das Modell wählen: Haiku 5.5, Sonnet 5.5 oder Opus selbst
    • Playbooks in Pflichtform schreiben
    • Unabhängige Teile parallel starten
    • Ergebnisse unabhängig nachprüfen
    • Bei Fehlschlag das Playbook schärfen und eskalieren
    • Bewährte Playbooks als Vorlage speichern

    Tut nicht

    • Aufgaben mit einem einzigen Tool-Aufruf oder Ein-Zeilen-Edits delegieren
    • Rückfragen an den Nutzer sowie Architektur- und Grundsatzentscheidungen abgeben
    • Opus als Subagent einsetzen
    • Den Agenten raten lassen: bei Abweichung gilt Abbruch und Meldung
    • Ein gemeldetes „pass“ ungeprüft übernehmen
    • Fehlerklassen ohne Gate als geprüft ausgeben: Sie werden als nicht geprüft gemeldet
    07 · Installation

    In vier Schritten einrichten

    Voraussetzung: Claude Code 2.1.293 oder neuer. Version prüfen mit claude --version. Bei älteren Versionen ist Haiku 5.5 nicht verfügbar.

    claude --version
    SCHRITT 1

    Marketplace hinzufügen

    claude plugin marketplace add 9fw2pq8sgb-art/claude-playbook-delegation
    SCHRITT 2

    Plugin installieren

    claude plugin install playbook@playbook-delegation
    SCHRITT 3

    In offenen Sessions aktivieren

    Kein Neustart nötig. In jeder bereits offenen Session (auch in der Desktop-App) einmal eintippen. Neue Sessions laden das Plugin automatisch.

    /reload-plugins
    SCHRITT 4

    Aufrufen

    Im Chat aufrufen. Alternativ genügt der Satz „delegier das“.

    /playbook:delegieren
    ALTERNATIVE

    Claude installieren lassen

    Diesen Satz in eine laufende Session kopieren. Claude installiert und sagt danach, was einzutippen ist.

    Installiere das Claude-Code-Plugin playbook@playbook-delegation aus dem Marketplace 9fw2pq8sgb-art/claude-playbook-delegation mit "claude plugin marketplace add" und "claude plugin install". Sag mir danach genau, was ich eintippen muss, damit es in dieser Session sofort aktiv ist.

    Liegt das Repository privat auf GitHub, ist für Schritt 1 ein Zugriff auf dieses Repository nötig. Ohne Berechtigung schlägt das Hinzufügen des Marketplace fehl.
